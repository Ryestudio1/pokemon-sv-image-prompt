# 宝可梦 朱／紫 实机截图视觉风格

本文档是 `pokemon-scarlet-violet-image-prompt` 的内置视觉规范。写提示词前先按本文档确定画风、玩法状态、HUD、中文 UI、区域发现地名 UI、宝可梦选取规则和元素池。

## 0. 这份文档怎么用

- 渲染方向由**单独一行心锚词 + 一行 `画风` 字段**集中锚定，其余字段保持极简，只列名词。
- 本文档里出现的具体外观描述（精灵球形状、太晶水晶形态、道馆形制、巢穴结构）是给 **prompt 自检和人工审图时的判断依据**，也是 `画风` 字段反向声明的取词来源。**不要把这些外观描述搬进 prompt 正文。**

## 1. 画面总目标

默认按「宝可梦朱紫原版实机截图复刻」方向写 prompt，不是宝可梦动画番剧截图，不是奇幻厚涂插画，不是写实动物摄影，不是现代旅游照。

- **画风字段标准写法**（直接复制使用）：

  ```text
  宝可梦朱紫原版实机游戏截图复刻
  画风：Nintendo Switch 宝可梦 朱／紫 开放世界实机截图风格；不要电影 CG、不要写实摄影、不要动画番剧赛璐璐截图、不要厚涂同人插画
  ```

  - `画风` 行只保留实机截图心锚 + 反向声明禁词。不要在这一行或任何其他字段追加 `高饱和卡通、强描边、柔光手绘、日系赛璐璐` 之类的风格串。
  - 其他字段（地点 / 画面要素 / 玩法时刻 / 宝可梦 / 帕底亚元素 / 地名 UI / HUD / 文字）**不要重复写**渲染词，也不要夹带「真实材质」「写实质感」「电影级光影」「毛发细节」等引导写实的副词。
  - 朱紫的渲染比塞尔达更「软」：模型圆润、色彩饱和偏暖、远景柔化。这些由心锚词自处理，不需要写出来。

- **相机**：第三人称游戏镜头，训练家在前景或中景的背影 / 侧后方，像玩家正在操作角色探索。`16:9 横图` 由出图 wrapper 的尺寸参数指定，prompt 字段里不需要再写画面比例。

- **角色造型（不要写进 prompt）**：朱紫的训练家有默认造型（学院制服 + 帽子 + 双肩背包）。**prompt 里不要展开**衣服颜色、领口、袖口、靴子、头发颜色长度、背包款式、耳饰等任何造型细节——写 `学院制服训练家` 就够，模型从「宝可梦朱紫原版实机游戏截图复刻」+ 这个词复现默认值。
  - **真正需要写进 prompt 的反例**：用户明确要求「换装」「穿道馆馆主制服」「指定角色性别 / 发型」等非默认造型时，才展开一句描述。否则不写。
  - **严禁把训练家写成动画主角**：不要出现「小智」「戴棒球帽的黑发少年 + 皮卡丘坐肩」这类动画形象。动画主角造型会把画面拉回番剧截图。

- **动作姿态（只写动词，不写身体微观细节）**：动作字段只写一个动作动词或极短动宾词组——`在投球` / `骑乘故勒顿冲刺` / `蹲下观察` / `举起洛托姆图鉴` / `在和宝可梦野餐`。**严禁**写身体微观细节：手臂挥到 45 度 / 球刚离手 10 厘米 / 重心前倾 / 指尖触球 / 起跳前最后一帧 / 瞳孔朝向 / 肌肉发力 等。也不要写抽象技能名（`使用捕捉技能`）。

- **场景特征保留**：真实景区的建筑、地形、水体、植被、文化符号要保留并融入帕底亚画面语言。
- **帕底亚允许现代设施（与塞尔达最大的差别）**：帕底亚原型是伊比利亚半岛，游戏世界里本来就存在公路、自行车道、风车、灯塔、港口、石桥、咖啡馆、城镇广场、电线与路灯、水道桥。**不要**为了「游戏化」把场景改成中世纪村落或废墟。现代旅游设施做**柔化转译**而不是删除：售票亭 → 友好商店、观景平台 → 观察台、游客中心 → 宝可梦中心、景区摆渡车站 → 城镇公交站、木护栏 → 圆润石栏。

- **人物全部 NPC 化**：游客、工作人员、排队人群、摊主、导游、路人都表现为学院学生、训练家、城镇居民、服务处员工或道馆工作人员——不要现代游客服装、写实路人、真实品牌服饰。
  - **NPC 服装黑名单**：禁止现代运动潮牌、卫衣球鞋、西装制服、真实品牌 Logo、汉服 / 唐装 / 旗袍 / 藏袍 / 苗银 / 纳西披星戴月等民族服装、僧侣袈裟、清代官服、民国学生装。NPC 必须从下列池子选一种：橘子学院制服、葡萄学院制服、道馆馆主装束、劲敌装束、城镇居民日常装（圆润卡通 3D 感）、服务处员工装、旅行者 / 训练家背包装。

## 2. 玩法状态 → HUD 矩阵（本 skill 的核心规则）

HUD 是真实游戏实况截图里**按当前玩法自然出现**的界面状态，不是堆满屏幕的信息图。朱紫的 HUD **完全由玩法状态决定**，所以模板里必须有一行 `玩法状态`，且 HUD 行复用同一个状态词。

| 玩法状态 | 自然出现的 HUD | 不应出现 |
| --- | --- | --- |
| 探索移动 | 几乎干净的画面；最多一个交互提示 | 血条、招式菜单、对手信息 |
| 野生遭遇 | 双方 HP 条、等级、名字、属性图标、招式菜单 | 太晶计时条、巢穴标记 |
| 捕捉 | 野生方 HP 条、名字、属性图标、精灵球数量、扔球提示文案 | 己方完整招式菜单 |
| 太晶对战 | 顶部大血条、太晶计时条、星数标记、太晶属性图标 | 双招式菜单同时铺满 |
| 野餐料理 | 极干净；只有料理 / 三明治制作界面元素 | 血条、招式菜单、对手信息 |

- 写 prompt 时**先决定这张图处于哪个状态**，再让 HUD 跟着变。多张图任务里不要每张都写同一个状态。
- 一张图只能一个状态。`极巨化` / `超级进化` 是剑盾和 XY 的机制，朱紫里没有，**禁止混用**。

### HUD 字段写得越简越好（重要）

**不要在 prompt 里写死 HUD 的具体内容、形状、位置、排列**——HUD 是生图模型该按「朱紫原版实机截图」心锚自然处理的元素，不是脚本字段。写细了模型会把字面意思塞进画面，生成贴纸式 / 信息图式的伪 HUD。

具体不要写：

- ❌ HUD 元素形状（例：`圆角矩形血条`、`带细白边的 HP 槽`、`绿色弧形能量条`、`六边形属性图标`）
- ❌ HUD 元素位置 / 排列（例：`左上角对手血条`、`右下角四格招式菜单`、`屏幕底部居中`）
- ❌ HUD 元素数量（例：`6 个招式格`、`3 颗精灵球剩余`、`5 星难度标记`）
- ❌ 具体数值（例：`HP 剩 1/3`、`Lv.68`）
- ✅ 一句方向性说明：`HUD：按朱紫原版「捕捉」界面自然出现，不堆满`
- ✅ 玩法关键到必须出现某元素时，用一句简短叙事带过：`HUD 体现捕捉进度反馈`
- ✅ 地名 UI、提示文案的**中文内容**还是要写（这是模型拿不到的信息），但不要写它在屏幕的哪一侧
- ✅ 允许出现的中文动词清单（例：`允许的交互动词：调查 / 对战 / 扔球 / 喂食`），由模型自己选 1-2 个落到画面

**核心准则**：HUD 字段理想长度 ≤ 1 行。出现「形状 / 位置 / 数量 / 排列 / 像素」几乎一定是错的。如果 HUD 缺失或位置错，那是**生图模型的复现失败**，交给用户出图后人工审，不是靠把 prompt 写得更细来强压。

## 3. 宝可梦选取规则（朱紫专属）

- **数量**：一张图 1-2 只。大型或传说宝可梦（故勒顿、基拉尼、卡比兽、暴鲤龙、快龙）一张图最多 1 只。禁止「一群皮卡丘」这类堆量描述——模型会画成廉价周边图。
- **命名**：只写官方简体中文名。确定的可以用：皮卡丘、伊布、喷火龙、妙蛙种子、杰尼龟、小火龙、耿鬼、路卡利欧、美纳斯、沙奈朵、暴鲤龙、化石翼龙、快龙、卡比兽、新叶喵、呆火鳄、润水鸭、故勒顿、基拉尼。**不确定的官方译名宁可不写种类，改写成「一只图鉴常见宝可梦」**；不要自创译名、不要写英文名、不要写日文罗马音。
- **版本心锚**：`故勒顿` 是朱版坐骑传说宝可梦，`基拉尼` 是紫版。用户没指定版本时，用 `朱紫默认造型` 且不绑定坐骑传说宝可梦；用户明确要朱或紫时才选对应传说宝可梦。
- **太晶化**：只在 `太晶对战` 状态出现，且只给画面主角那 1 只宝可梦挂太晶。写法就一行 `太晶属性：火`，不展开水晶颜色形状。野生场景、探索场景、野餐场景**禁止**出现太晶。
- **头目宝可梦**：`头目` 只和 `太晶对战` / 巢穴搭配使用，一张图最多 1 只，写法 `头目宝可梦`，不要描述体型倍数和光环颜色。
- **外观不展开**：不要写宝可梦的毛色渐变、眼睛高光、鳞片纹理、体型比例修正。名字 + 数量就够了。
- **互动关系要落地**：宝可梦要和真实景点地形产生关系——趴在石栏上、藏在桥洞下、在湖面上浮出半个头、蹲在野餐布旁，而不是悬浮在场景上的贴纸。

## 4. 区域发现地名 UI 样式

场景图默认写一行 `地名 UI 文字（区域发现）`，用朱紫进入新区域时浮现的区域名版式。**朱紫的地名卡比塞尔达更简单：单行主地名 + 一行更小的副标题，没有三段式，没有两侧短横线装饰。**

- **主行**：中等大小圆润白字，带很细的描边，居中浮现
- **副行**：小字副标题（主地名的上级真实区域），紧跟主行下方
- 整体淡入淡出感、无重阴影
- **没有矩形边框、没有深色底纹、没有花纹 / 徽章 / 精灵球图形装饰**
- **字号约束**：主地名文字宽度不超过画面横向 1/2，高度不超过画面纵向 8%；不是旅游海报标题级别的占屏大字

**所有 UI 地名文字必须是真实中文地名，严禁帕底亚游戏内地名**：区域发现 UI、路牌、招牌、地图标记、NPC 对话里**所有可读地名文字**，只能写本图对应的真实中国景区 / 省市 / 景点名（例：中间行「杭州·苏堤」、下方「浙江·杭州」；中间行「北京·颐和园」、下方「北京·海淀」）。**禁止**出现「帕底亚」「酿光市」「星尘镇」「染勿朵」「钵卷」等任何游戏内城镇区域名。原因：UI 里用游戏内地名会让画面变成「朱紫截图」而不是「真实景区的宝可梦化呈现」，抹掉地点叙事。prompt 里 `帕底亚地图区块：XXX` 这个字段名是写给模型理解画风用的锚点，**UI 文字必须落到 XXX（真实地名），不能把「帕底亚」搬进 UI**。

**固定 prompt 写法**（每张场景图直接替换地名使用）：

```text
地名 UI 文字（区域发现）：中间「<真实主地名>」 / 下方「<真实上级区域名>」；单行圆润白字带细描边、淡入、无矩形边框、无深色底纹
```

如果场景没有真实上级区域，副行用简短中文主题归属，例如 `古代遗迹研究区`、`海边驿站外围`；不要写宣传语。

**禁止做成**：旅游海报标题、宣传横幅、说明字幕、右上角固定标签、二维码、emoji、精灵球形状 Logo。

## 5. UI 文字中文化规则

画面里的可读文字要像简体中文版游戏 UI，**不要出现英文界面词**。

### 允许的原版中文文案

```
野生的喷火龙出现了！
快扔球！
欢迎来到图鉴！
效果绝佳！
对手畏缩了！
道馆挑战
太晶对战
宝可梦中心
友好商店
```

### 中文交互动词清单

```
调查、对战、扔球、捕捉、喂食、交换、登录图鉴、骑乘、奔跑、野餐、拍照
```

**严禁出现的英文 UI 词**：WILD、APPEARED、GO、BATTLE、RUN、THROW、POKEMON、Dex、Raid、Tera 等。招式名如需出现必须用官方中文招式名（如 `喷射火焰`、`水炮`）；**不确定的招式宁可不写**，不要造词。

### 文字无法清晰时

优先**减少**画面内文字：只保留地名卡 + 1 处交互提示；不要乱码、伪英文、外挂字幕、旅游说明文字、图鉴长段落介绍。

## 6. 帕底亚游戏元素池

按地点气质和画面构图，从下列六大类挑选组合：

### 主角与人物
学院制服训练家、橘子学院学生、葡萄学院学生、劲敌、道馆馆主、四天王成员、校长、老师、博士、城镇居民、服务处员工、旅行训练家、摄影师

### 宝可梦
初始宝可梦（新叶喵 / 呆火鳄 / 润水鸭）、传说宝可梦（故勒顿 / 基拉尼）、图鉴常见宝可梦、野生宝可梦、头目宝可梦、太晶宝可梦、闪光宝可梦（需用户明确要求）、宝可梦群体（最多 2 只）

### 建筑与设施
道馆（带观众席的竞技场形制）、太晶巢穴（地面圆形坑口 + 垂直光柱）、宝可梦中心、友好商店、橘子学院 / 葡萄学院校舍、观察台、野餐点、瞭望塔、石桥、港口与灯塔、风车、城镇广场、水道桥、自行车道、露营点

### 道具与界面
精灵球、高级球、伤药、洛托姆图鉴、手机洛托姆、背包、太晶碎块、招式学习器、孵蛋蛋、喂食材料、三明治、野餐布、料理锅、图鉴登录界面、地图导航界面、交换界面

### 玩法与 HUD
双方 HP 条、等级与名字标签、属性图标、招式菜单、精灵球剩余数、扔球提示、太晶计时条、巢穴星数标记、道馆挑战标记、图鉴登录提示、天气与时间显示、骑乘加速反馈、捕捉成功反馈

### 环境玩法
草丛晃动、水面涟漪、可攀爬岩壁、可滑翔气流、脚印轨迹、远处飞行宝可梦剪影、洞穴入口、迷雾山谷、麦田风纹、日落湖面、可交互路牌、宝可梦出没标记

## 7. 必须避免清单（出图后人工审图判断依据）

- **画风漂移**：宝可梦动画番剧赛璐璐截图、厚涂同人插画、写实动物摄影、毛绒周边实拍、塑料感 3D 渲染、电影 CG 光线追踪、HDR 真实光影
- **角色错位**：动画主角造型（黑发棒球帽少年 + 皮卡丘坐肩）、写实现代游客、真实品牌服饰、民族服装、成年写实模特比例
- **宝可梦错位**：超过 2 只、写实毛发鳞片质感、混入朱紫不存在的机制（极巨化 / 超级进化）、皮卡丘泛滥、自创宝可梦
- **太晶错位**：太晶画成彩虹钻石堆 / 魔法阵 / 玻璃宝石雨；正解是**单色六棱水晶冠 + 一道垂直光柱**；非太晶对战状态出现太晶
- **精灵球错位**：球体变形、按钮偏移、画成大师球或豪华球泛滥；正解是**上半红下半白 + 中央白按钮**
- **道馆错位**：画成现代 NBA 体育馆 / 电竞馆；正解是**带观众席与竞技台的圆形竞技场**
- **巢穴错位**：画成悬浮天空之城 / 魔法阵；正解是**地面圆形坑口 + 从坑心升起的垂直光柱**
- **HUD 错位**：写死形状 / 方位 / 数量 / 数值、UI 堆满屏幕、现代 App 导航栏、信息图排版
- **地名 UI 错位**：游戏内地名进入 UI、旅游海报大字、深色底纹矩形标签、两侧装饰花纹、宣传语
- **文字错位**：英文界面词、乱码、伪汉字、图鉴说明长段落、二维码、emoji、水印、Logo
- **结构错位**：回退到 15 行以上的长分镜、前中远景分层、材质颜色光线堆叠、写实景区地名堆砌

## 8. 输出自检

- 行数 10-14 行，行序与模板一致
- `画风` 行完整，且没有风格串（赛璐璐 / cel-shading / 厚涂 / 手绘）
- 只写了 1 个 `玩法状态`，HUD 行复用同一个状态词
- `宝可梦` ≤ 2 只，全是官方简体中文名，大型 / 传说最多 1 只
- 非太晶对战状态里没有出现太晶
- 所有可读 UI 地名是真实中文地名，没有帕底亚地名
- HUD 行 ≤ 1 句，没有出现形状 / 方位 / 数量 / 数值
- 没有任何材质、光线、焦段、身体微观动作描述
